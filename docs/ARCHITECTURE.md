# Архитектура USTA

Текущие репозитории сохраняются:
- usta-webapp — Next.js: web, будущий Telegram Mini App и административные экраны.
- usta_bot — Python/aiogram: вход из Telegram и открытие web-приложения.

Целевая схема: каналы Web/Telegram → единый серверный API → PostgreSQL.
AI, платежи, уведомления и медиа подключаются через отдельные адаптеры.
Этот API и PostgreSQL пока не реализованы; JSON и данные в компонентах являются
прототипом. Бот не должен независимо хранить вторую копию заказов.

Сервер определяет user_id и role из проверенной сессии, а не из тела запроса.
Telegram initData проверяется сервером, включая подпись и допустимый возраст.
Cookie админки текущего прототипа не заменяет будущую авторизацию клиентов.

Деньги — целые значения в минимальных единицах с явной валютой.
Время — UTC в базе и локальное отображение. Адрес и точная геолокация
доступны только участникам заказа с необходимыми полномочиями.
Загрузки — объектное хранилище, проверка типа/размера и ограниченные ссылки.
Платёжные webhook — проверка подписи и ключ идемпотентности.
AI не вправе самостоятельно менять цену, списывать деньги или назначать
Verified. Для каждой рекомендации сохраняются источник и решение пользователя.

Первый релиз: один город/набор категорий определяется владельцем до наполнения
каталога. Публичные обещания SLA и гарантий появляются после готовности операций.
