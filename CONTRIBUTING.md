# Разработка USTA

Основная ветка — main. Изменения проходят через отдельную ветку и pull request.
Перед слиянием: CI, проверка поведения и связанных ограничений. Не включайте
автоматическое слияние до появления стабильных проверок.

CODEOWNERS направляет изменения владельцу; сам по себе он не защищает ветку.
После первого успешного CI настройте правило main: запрет force push и удаления,
обязательный pull request и обязательный статус CI. Для единственного владельца
не требуйте одобрения собственного PR.

Секреты задаются в окружении хостинга, не в коде. Раздельные значения для
development, staging и production. Новые API проверяют пользователя и его
право на конкретный объект на сервере, независимо от защиты страниц.

Функции из docs/ROADMAP.md считаются планом до реализации и проверки критериев.
