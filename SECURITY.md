# Безопасность

Не публикуйте секреты и данные клиентов в Issues. Для уязвимостей используйте
приватный канал владельца или GitHub Private vulnerability reporting, если он включён.

В репозиторий нельзя добавлять .env, ключи, Telegram session-файлы, платёжные
данные и реальные документы пользователей. .gitignore не удаляет старую историю.

Перед production:
- заменить ранее опубликованные пароли/токены;
- завершить ранее сохранённую Telegram-сессию в настройках Telegram;
- установить секреты в окружении хостинга;
- подключить общую защиту от перебора, мониторинг и резервное копирование;
- проверить права пользователя на каждый объект и административный API.

Наличие CI не означает завершённый аудит безопасности.
